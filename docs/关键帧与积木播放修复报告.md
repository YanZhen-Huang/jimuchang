# 关键帧与积木播放修复报告

- 日期：2026-11-06
- 项目：积木剧场（JimuChang）
- 基线版本：v0.4.2
- 范围：播放事件调度、关键帧编辑器、自动化回归

## 摘要

本轮修复了两个会直接表现为“点了完全没反应”的故障：

1. 在章节页搭建的「当演示开始」脚本能够保存和编译，但播放时没有被调度。
2. 关键帧编辑器的「完成」和「试播」调用了不存在的重置方法；「完成」因此在关闭面板前抛出异常。

两个问题都已修复、重新编译并覆盖安装版，同时补充了自动化回归测试。

## 问题一：积木播放时无反应

### 现象

用户在当前章节页中搭建积木后点击播放，画面没有执行对应动作，也没有明显错误提示。

### 根因

编译阶段会把章节页中的「当演示开始」帽子编译到 `scripts.scenes[chapterId]`，但播放启动逻辑只检查 `scripts.global`：

```js
this.scripts.global.filter(s => s.kind === 'onStart')
```

因此章节页里的开始事件虽然存在且有效，却从未进入运行队列。

### 修复

- 新增 `Executor.onStartScripts()`，统一收集：
  - 全局页中的开始事件；
  - 所有章节页中的开始事件；
  - 元素自身事件仍沿用原有独立调度。
- 播放开始时统一执行上述脚本，消除章节页脚本静默失效。
- 增加播放前预编译检查：如果工作区只有动作块、没有橙色「当…」事件帽，会在进入全屏前明确提示原因。

## 问题二：关键帧动画“完成”按钮无反应

### 现象

点击关键帧动画面板右上角的「完成」按钮后，面板不关闭，界面看起来没有任何变化。

### 根因

`Keyframes.close()` 在隐藏面板前调用了不存在的 `this.reset()`：

```js
if (dom) this.reset(el, dom);
this.panelEl.classList.add('hidden');
```

因为 `Keyframes` 对象没有 `reset` 方法，第一行抛出 `TypeError`，后面的隐藏面板代码永远不会执行。

「试播」按钮也存在同一错误，同样调用了不存在的 `this.reset()`。

### 修复

- 新增 `Keyframes.resetElement()`：
  - 停止正在运行的 `requestAnimationFrame`；
  - 结束等待中的试播 Promise；
  - 清理动画内联状态；
  - 按元素基础数据恢复位置、尺寸、旋转和透明度。
- 「完成」和「试播」统一调用正确的重置逻辑。
- 面板关闭使用 `try/finally` 保护：即使状态恢复失败，也保证面板能够关闭并记录警告。

## 结论

本轮两个“无反应”问题均由事件或清理方法未接入真实执行链导致，不是用户项目数据损坏。修复后，章节页开始脚本可正常执行，关键帧编辑器可以停止试播并可靠关闭。
